# TBM 안전점검 기록 시스템

작업자가 출근하면서 QR을 찍으면 그날 TBM이 자동으로 열리고, 팀장은 현장 사진만 올려
상신하면 되는 일일 TBM(Tool Box Meeting) 기록·결재 시스템입니다.

"형식적으로 나중에 몰아서 작성하는 것"을 막는 데 초점이 맞춰져 있습니다.

## 어떻게 동작하는가

```
06:00  작업자가 지문인식기 옆 QR을 스캔
       → 본인 확인(첫 1회만) → 출석 기록
       → 그날 첫 스캔이면 팀의 TBM이 자동 생성되고
         템플릿(매일 동일한 교육 항목 + 상시 위험요인)이 자동으로 채워짐

08:00  팀장이 TBM을 열어 현장 사진을 촬영·업로드
       → 사진 EXIF에서 촬영 시각·GPS를 추출해 자동 검증
       → 필요한 부분만 손질하고 결재 상신

08:30  마감. 이후 상신은 '지연 상신'으로 표시됨

이후   안전관리자가 결재함에서 승인 또는 반려
       본사는 대시보드에서 전 사업장 이행률과 경고 건을 확인
```

### 자동 검증 (사후 작성 억제)

사진을 올릴 때마다 4가지를 확인해 기록에 남깁니다. 결재자와 본사 대시보드에
경고로 표시되며, 승인 자체를 막지는 않습니다(판단은 사람이 합니다).

| 플래그 | 걸리는 조건 |
| --- | --- |
| 지연 상신 | 사업장 마감 시각을 넘겨 상신 |
| 촬영일 불일치 | 사진 촬영일(EXIF)이 작업일과 다름 |
| 현장 이탈 촬영 | 사진 GPS가 사업장 반경 밖 |
| 촬영 정보 없음 | EXIF가 없음 (캡처 화면·카톡 재전송 의심) |

> EXIF의 `DateTimeOriginal`에는 타임존이 없습니다. 서버가 UTC로 도는 Vercel에서
> 9시간이 어긋나지 않도록 KST 벽시계로 직접 해석합니다 (`lib/exif.ts`).

## 역할

| 역할 | 할 수 있는 일 |
| --- | --- |
| `HQ_ADMIN` (본사) | 전 사업장 조회, 전사 공통 템플릿 관리, 대시보드 |
| `SITE_MANAGER` (안전관리자) | 소속 사업장 결재, 사업장 설정·명부·QR 관리 |
| `TEAM_LEAD` (작업팀장) | 담당 팀 TBM 작성·상신 |

작업자는 **계정이 없습니다.** QR 스캔만으로 출석합니다.

## 기술 스택

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS v4 ·
Prisma + PostgreSQL · NextAuth v5 · Vercel Blob

## 로컬 실행

### 1. 데이터베이스 준비

[Neon](https://neon.tech)에서 무료 Postgres를 만듭니다. 리전은
`AWS / Asia Pacific (Seoul)`을 권장합니다. 생성 후 **Pooled connection string**을
복사하세요.

### 2. 환경변수

`.env.local`을 열어 `DATABASE_URL`을 방금 복사한 값으로 바꿉니다.
(`AUTH_SECRET`은 이미 생성되어 있습니다.)

```
DATABASE_URL="postgresql://...?sslmode=require"
```

### 3. 스키마 반영 + 데모 데이터

```bash
npm run db:push     # 테이블 생성
npm run db:seed     # 사업장 2곳, 계정, 작업자, 교육 템플릿 생성
```

시드가 끝나면 로그인 계정과 **출석 QR 링크**가 콘솔에 출력됩니다.

| 계정 | 역할 |
| --- | --- |
| `hq@example.com` | 본사 관리자 |
| `manager.f01@example.com` | 제1공장 안전관리자 |
| `lead.f01.1@example.com` | 조립1반 팀장 |

비밀번호는 모두 `tbm1234!` 입니다. (`SEED_PASSWORD` 환경변수로 바꿀 수 있습니다.)

### 4. 실행

```bash
npm run dev
```

http://localhost:3000 접속. 출석 QR은 로그인 후 **관리 → 출석 QR**에서 인쇄합니다.

> 휴대폰으로 QR을 테스트하려면 PC와 폰이 같은 네트워크에 있어야 하고,
> `NEXT_PUBLIC_APP_URL`을 `http://<PC의 IP>:3000`으로 바꿔야 합니다.

## 실제 데이터 넣기

시드 데이터는 데모입니다. 실제 운영 데이터는 **모두 관리 화면에서 직접 넣습니다.**

본사 계정으로 로그인 → **관리** 탭 → 안내된 순서대로:

1. **사업장** 생성 → 설정에서 **위도·경도** 입력
2. **계정** — 안전관리자·팀장 로그인 계정
3. **작업팀** — 팀 생성 후 팀장 지정
4. **작업자 명부** — 엑셀 양식 내려받아 채운 뒤 일괄 업로드
5. **교육 템플릿** — 매일 교육할 항목 조정
6. **출석 QR** — 인쇄해서 부착

데모 사업장은 관리 → 사업장에서 삭제하면 소속 데이터가 함께 정리됩니다.

자세한 내용과 엑셀 업로드 규칙은 [DEPLOY.md](./DEPLOY.md#6-초기-데이터)를 보세요.

## 운영 시 자주 걸리는 것

1. **사업장 좌표를 안 넣으면** 사진 GPS 대조를 통째로 건너뜁니다. 경고가 안 뜨는 게
   아니라 검증 자체가 안 켜집니다.
2. **팀이 지정되지 않은 작업자**는 QR을 찍어도 출석이 기록되지 않습니다.
3. **팀장이 없는 팀**은 그 팀 TBM을 작성할 사람이 없습니다.
4. **시간 설정**(마감·지각 기준·체크인 창)은 사업장별로 다르게 둘 수 있습니다.

## 구조

```
app/
  (app)/          로그인이 필요한 화면 (TBM, 결재함, 대시보드, 관리)
  c/[token]/      작업자용 공개 QR 체크인 페이지 (로그인 불필요)
  api/tbm/[id]/photos/   사진 업로드 + EXIF 검증
actions/          서버 액션 (TBM, 체크인, 관리)
lib/
  kst.ts          KST 기준 날짜 계산 (서버는 UTC라 직접 다룬다)
  exif.ts         EXIF 촬영시각·GPS 추출
  tbm.ts          TBM 자동 생성, 사진 검증, 플래그 계산
  authz.ts        역할·사업장 격리
prisma/schema.prisma
```
